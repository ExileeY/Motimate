# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

> **This is a native SwiftUI iOS app.** It began life as an Expo/React Native app (removed in commit `a431583`, "Removed RN application") and was ported 1:1 to SwiftUI. That history is why many files carry `/// Port of src/...` comments and mirror an old RN module layout — those comments point at code that no longer exists here; treat the Swift as the source of truth. There is **no** `package.json`, `app/`, `src/`, Expo, or React Native in this repo.

## Commands

The Xcode project is **generated by [XcodeGen](https://github.com/yonatanp/xcodegen)** from [project.yml](project.yml) — the `.xcodeproj` is checked in but regenerable. Edit `project.yml` (or add files under `Motimate/`), then regenerate; do **not** hand-edit `Motimate.xcodeproj/project.pbxproj`.

```bash
xcodegen generate     # regenerate Motimate.xcodeproj from project.yml (run after adding/removing/moving files)

# Build (pick an installed simulator name from `xcrun simctl list devices available`)
xcodebuild build -scheme Motimate -destination 'platform=iOS Simulator,name=iPhone 16 Pro'

# Run the whole test suite
xcodebuild test -scheme Motimate -destination 'platform=iOS Simulator,name=iPhone 16 Pro'

# Run a single test class or method (repeat -only-testing: for more)
xcodebuild test -scheme Motimate -destination 'platform=iOS Simulator,name=iPhone 16 Pro' \
  -only-testing:MotimateTests/MoodTests
xcodebuild test -scheme Motimate -destination 'platform=iOS Simulator,name=iPhone 16 Pro' \
  -only-testing:MotimateTests/MoodTests/testEnergeticAtZeroSteps
```

There is no linter configured. `xcodebuild build` (or Xcode) is the typecheck. Deployment target is **iOS 15.1**, Swift 5.

**IMPORTANT — new files must be added to the target.** A newly created `.swift` file won't compile until it's part of the `Motimate` target. Either regenerate with `xcodegen generate` (it globs `Motimate/` per `project.yml`) or add it to `project.pbxproj`. If a brand-new file's symbols read as "not found," this is almost always the cause.

**Verifying mood visuals without walking:** in `DEBUG` builds, tapping the pet cycles `ENERGETIC → CALM → TIRED → SAD` ([HomeView.swift](Motimate/Views/HomeView.swift) `cycleMood`). The override is local `@State` layered over the live `DailyStepsModel`, so you can preview every mood on the Simulator, which has no pedometer. Most views also carry `#Preview` blocks for isolated inspection.

**Device requirements:** real step data comes from `CMPedometer` (Core Motion) and needs a **physical device** — the iOS Simulator has no pedometer, so `StepReader.requestPermission()` returns `.unavailable` and the app renders a resting state with a notice. Android does not exist in this codebase.

## Architecture

Motimate is an **anti-nagging movement companion** whose home screen *is* a virtual pet (one of eight interchangeable pets — Mochi, Bulbashik, Dog, Octopus, Arutic, Khinklear, Tomato, Schnauzer; the user picks the active one) whose mood is **inverted** from typical fitness apps — fewer steps → energetic pet ("Walk with me?"); moderate steps → calm; many steps → tired/asleep, because rest is framed as the reward. Four screens, each wired from `HomeView` via a hidden `NavigationLink`: [HomeView.swift](Motimate/Views/HomeView.swift), [SettingsView.swift](Motimate/Views/SettingsView.swift) (daily-goal editor, mode picker, pet picker), [PodiumView.swift](Motimate/Views/PodiumView.swift) (this week's accessory challenge — preview it on your pet, watch week-to-date progress, equip it once earned), and [WardrobeView.swift](Motimate/Views/WardrobeView.swift) (the whole accessory collection, grouped by slot).

The entire UI flows from **five `ObservableObject`s** injected as `@EnvironmentObject` in [MotimateApp.swift](Motimate/MotimateApp.swift):

```
SettingsStore          → { goal, gameMode, petId, autoNightEnabled, ready }   (persisted, app-wide)
DailyStepsModel        → { steps, mood, progress, permission, loading, error }
   │   subscribes to SettingsStore.$goal / .$gameMode (Combine) and recomputes
   │   StepsConvertor.toMood(steps, goal, mode, hour) / toProgress(steps, goal)
CelebrationStore       → once-per-day confetti gate (motimate.celebrated)
AccessoryStore         → { owned, equipped } accessory ownership + per-slot equips
WeeklyChallengeModel   → { weeklySteps, challenge } the podium's weekly challenge
   │   subscribes to DailyStepsModel.$steps (Combine); weeklySteps = priorDays + today
   ▼
mood (enum) fans out to every view via [Mood: …] lookup tables, resolved for the
active Theme through ThemeTokens.for(theme):
  PhoneCanvas (background gradient + emitters) · TopBar (status dot) ·
  PetStage → Glow + the active pet Body (pose + animation) ·
  MovementCard (bar %) · the active pet's MessageSet
```

Key conventions:

- **`Mood` is a 4-case enum** (`energetic`/`calm`/`tired`/`sad`) in [Mood.swift](Motimate/Domain/Mood.swift), used both as a runtime value and as the key type for `[Mood: …]` tables. To add per-mood behavior, add an entry to the relevant table (gradients/glow/dot in the [Constants/Theme/](Motimate/Constants/Theme/) token tables — `ScreenBgTokens`/`StageGlowTokens`/`StatusDotTokens` — motion in `PetStageMotion`, per-pet text in `Domain/Messages/`) — don't branch on mood ad hoc. `sad` is special: it's a REAL-mode-only overlay (see below), so several `switch mood` sites treat it like `energetic`.
- **All step→state conversion lives in `StepsConvertor`** ([Mood.swift](Motimate/Domain/Mood.swift)). Base thresholds are the single `MOOD_MAX_RATIO` map, expressed as **fractions of the goal**. `toMood` then applies the **SAD overlay**: in `.real` mode, an `energetic` pet turns `sad` once the hour is past `MORNING_END_HOUR` (noon) — "you should have moved by now." `.standard` mode never produces `sad`. This is the only place numbers become moods.
- **App-wide state is one `SettingsStore`, not scattered constants.** [SettingsStore.swift](Motimate/Persistence/SettingsStore.swift) holds `goal` / `gameMode` / `petId` / `autoNightEnabled` / `hapticsTabEnabled` / `hapticsAnimationEnabled`, each backed by a `PersistedStorage<T>` ([PersistedStorage.swift](Motimate/Persistence/Storages/PersistedStorage.swift)) — a small value type bundling `key`/`decode`/`encode`/`normalize`/`fallback` over `UserDefaults`. Per-field factories (`GoalStorage.make`, `GameModeStorage.make`, `PetStorage.make`, `AutoNightStorage.make`, and the two haptics stores) live under [Storages/Settings/](Motimate/Persistence/Storages/Settings/) beside their bounds/normalization ([GoalStorage.swift](Motimate/Persistence/Storages/Settings/GoalStorage.swift): `GOAL_DEFAULT`/`MIN`/`MAX`/`normalizeGoal`, etc.). Every setter clamps + returns the stored value so a UI field can snap to it; a `ready` flag replaces throwing on hydration. Persistence keys are `motimate.*`.
- **Theming is day/night, resolved per-frame from the system `colorScheme`.** [Theme.swift](Motimate/Domain/Theme.swift) is a `Theme` enum (`.day`/`.night`); `Theme.resolve(autoNightEnabled:isDark:)` returns `.night` only when the user opted into auto-night *and* the device is in dark mode. `HomeView`/`SettingsView` read `@Environment(\.colorScheme)`, compute `settings.resolvedTheme(isDark:)`, and inject `.environment(\.theme, theme)`; a DEBUG-only `SettingsStore.themeOverride` lets a tap cycle `nil → night → day` (`HomeView.toggleTheme`). Theme-aware tokens come from `ThemeTokens.for(theme)` ([ThemeTokens.swift](Motimate/Constants/Theme/ThemeTokens.swift)) — read those (or `@Environment(\.themeTokens)`), **not** the `Colors` alias in [Palette.swift](Motimate/Constants/Theme/Palette.swift), which is `Palette.day` for previews only. Each token conforms to `MoodToken` ([MoodToken.swift](Motimate/Constants/Theme/MoodToken.swift)): a `day: [Mood: Value]` table plus a single flat `night: Value`, so day is per-mood while night is one look across all moods.
- **A day's goal completion fires confetti once.** [CelebrationStore.swift](Motimate/Persistence/CelebrationStore.swift) is a third injected `@EnvironmentObject` persisting the last celebrated day (`motimate.celebrated`, a `yyyy-MM-dd` string); `HomeView.maybeCelebrate()` shows the [Confetti](Motimate/Components/Confetti/Confetti.swift) overlay when `dailySteps.progress >= 1` and `shouldCelebrate()` is still true, then calls `markCelebrated()`. In DEBUG, cycling the mood also `resetToday()`s so the confetti replays.
- **`DailyStepsModel` recomputes reactively via Combine.** It sinks `SettingsStore.$goal` and `.$gameMode`; because `@Published` fires in `willSet`, the sink recomputes from the **freshly-emitted value passed into the closure**, not by re-reading the (still-stale) store — see the comment in [DailySteps.swift](Motimate/Steps/DailySteps.swift). It subscribes to an injected `HourClock` (see below) so a REAL-mode energetic pet flips to SAD past noon while the screen stays open — the model itself owns no `Timer` and never reads `Calendar`. It's `@MainActor`.
- **The active pet is user-selectable runtime state, sourced from a registry.** [Pet.swift](Motimate/Domain/Pet.swift) maps each `PetId` enum case to a `PetDefinition` (`name` + a `body: (Mood, CGFloat?) -> AnyView` closure + `pickMessages`) in the `PETS` table, and exports `PET_IDS` + `PET_ID_DEFAULT` + `petDefinition(_:)` (which falls back to the default). **To add a pet:** build its `Body` (a `mood`-prop SwiftUI view) + a `Domain/Messages/<name>Messages.swift`, then add one `PETS` entry — it appears in [PetPicker.swift](Motimate/Components/PetPicker.swift) automatically. Glow is deliberately *not* part of a pet — it stays pet-agnostic in `PetStage`.
- **Per-pet copy is randomized once per screen appearance.** `pickMessages(pools)` ([MessageSet.swift](Motimate/Domain/MessageSet.swift)) picks one `MessageSet` (`headline`/`subtitle`/`meta`/`footer`) per mood from that pet's pools; `HomeView` calls it in `onAppear` and on `petId` change.
- **Accessories are earned only through the podium's weekly challenge.** One accessory per ISO week (Mon–Sun), always one the user doesn't own; walk its `weeklyStepGoal` (a **week** total, not a day's) and it's yours permanently. There is no other unlock path — a daily rule would empty the pool in one good day and strand the podium on its placeholder forever. The pieces: [WeekMath.swift](Motimate/Domain/WeekMath.swift) (ISO week arithmetic, Monday-pinned regardless of locale), [WeeklyChallenge.swift](Motimate/Domain/WeeklyChallenge.swift) (the pure `select(weekIndex:owned:)` cycle over `Accessory.rotationOrder`; `nil` = all owned → `WeeklyPlaceholderCard`), [WeeklyChallengeStore.swift](Motimate/Persistence/WeeklyChallengeStore.swift) (persists the origin week + the frozen pick), and [WeeklyChallengeModel.swift](Motimate/Steps/WeeklyChallengeModel.swift) (week-to-date steps + the unlock). Three things are load-bearing and easy to undo by accident:
  - **The pick is frozen per week, not derived.** `select` is a function of `owned`, which changes the instant the user earns the item — recomputing on read swaps the podium's item mid-week and yanks the prize away at the moment of victory. `WeeklyChallengeStoreTests.testEarningMidWeekDoesNotSwapTheItem` is the guard.
  - **The week index is install-relative** (`weeksBetween(origin, now)`), so every new user's week 1 is `rotationOrder[0]`. That makes `rotationOrder` a difficulty ramp — easiest first. Using the global ISO week number instead would drop each new user at an arbitrary point in the cycle.
  - **Rollover is inferred, never detected** — same trick as `CelebrationStore`: no timer, no clock protocol, just a stored value compared against a lazily-computed current one. `HourClock` is `Int`-typed and change-gated, so it structurally *cannot* express a week.
- **Pedometer access is behind one `StepReading` protocol** ([StepReading.swift](Motimate/Steps/StepReading.swift)) — `requestPermission` / `getTodaySteps` / `getSteps(from:to:)` / `subscribe`. `getSteps(from:to:)` backs the weekly total (and `getTodaySteps` now delegates to it); note **CoreMotion only retains 7 days**, which week-to-date fits with no margin — anything reaching further back needs persisted daily snapshots. `StepReader` ([StepReader.swift](Motimate/Steps/StepReader.swift)) is the `CMPedometer` impl; `UnavailableStepReader` is the null impl. Tests inject a fake reader through `DailyStepsModel(reader:)`.
- **The current hour is behind an `HourClock` protocol** ([HourClock.swift](Motimate/Steps/HourClock.swift)), mirroring `StepReading` — `hour` / `subscribe(onHour:)` / `refresh()`. `SystemHourClock` owns the ~60s `Timer` + `Calendar` read and fires only when the hour changes; tests inject a `FakeHourClock` and `push(_:)` a new hour through `DailyStepsModel(clock:)`. `DailyStepsModel.refresh()` (called on foreground) forwards to `clock.refresh()` and re-anchors the reader.
- **Failure is state, never a throw.** `DailyStepsModel` surfaces denied/unavailable permission and errors as `@Published` fields; the screen degrades to a resting pet + a small notice. `StepReader` resolves permission errors to a `PermissionState` and reads to `0`.
- **Responsive sizing is one clamped scale factor.** [ResponsiveScale.swift](Motimate/Helpers/ResponsiveScale.swift) `computeScale(height)` derives a 0.85–1.15 factor from window height (812pt reference) and feeds pet sizing + heading caps.
- **Haptics are two independent opt-in toggles fired through one stateless service.** [HapticsService.swift](Motimate/Helpers/HapticsService.swift) is an `enum` with no state — `impact(style, enabled:)` (a single `UIImpactFeedbackGenerator` tap) and `celebration(enabled:)` (a hard-coded rising-then-fading roll over ~0.75s for goal completion); each `guard enabled else { return }` up front, so **callers always pass the flag, never gate themselves**. The two flags are separate settings: `settings.hapticsTabEnabled` gates tap feedback (pet tap in [HomeView.swift](Motimate/Views/HomeView.swift), [PetPicker.swift](Motimate/Components/PetPicker.swift)/[ModePicker.swift](Motimate/Components/ModePicker.swift) selection, the settings toggle itself) and `settings.hapticsAnimationEnabled` gates the confetti celebration. Both default **off**, persist via `HapticsTapStorage`/`HapticsAnimationStorage` (both conform to `HapticsStorageKind` in [BaseHapticsStorage.swift](Motimate/Persistence/Storages/Settings/Haptics/BaseHapticsStorage.swift), which supplies the shared `Bool`↔`"true"/"false"` codec + `make`), and are edited in `SettingsView` via `HapticSwitchToggleStyle` ([HapticToggle.swift](Motimate/Components/HapticToggle.swift), the `.hapticSwitch(enabled:tint:)` custom toggle). Haptics do nothing on the Simulator — needs a physical device.

### Pet rendering (the deliberate technical choice)

Pets are hand-authored with **SwiftUI `Path`/`Shape` + gradients**, not stock SF Symbols or `RoundedRectangle`s. They are direct ports of `react-native-svg` originals, so the codebase carries a small **SVG-compat layer** so the RN `d`-strings and gradient specs port verbatim:

- [SVGPath.swift](Motimate/Components/Pets/Shared/SVGPath.swift) — `svgPath(_ d:)` parses an SVG path-data string (`M/L/H/V/C/Q/A/Z`, absolute + relative) into a `Path` (elliptical arcs are expanded to cubic Béziers); `SVGShape` wraps it as a `Shape`.
- [RoundedBoxPath.swift](Motimate/Helpers/RoundedBoxPath.swift) — `roundedBoxPath(x,y,w,h,corners)` builds a box with four **independent** per-corner elliptical radii (`[(rxFrac, ryFrac)]` for `[TL,TR,BR,BL]`) — the SVG/CSS `border-radius` shape RN used, which `RoundedRectangle` can't express. `roundedBoxString` emits the identical geometry as a `d`-string for snapshot tests.
- [SVGGradient.swift](Motimate/Components/Pets/Shared/SVGGradient.swift) — `radialGradient`/`linearGradient`/`verticalLinearGradient` + `GStop("#hex", offset, opacity)` port SVG `<RadialGradient>`/`<LinearGradient>`. **Framing gotcha (read the header comment):** a SwiftUI gradient resolves `UnitPoint`/`endRadius` against *the frame the shape is drawn in*, whereas SVG resolves them against *the shape's own bounding box*. So a gradient-filled sub-shape (ear, muzzle) must be drawn in a frame sized to that shape and `.position(...)`ed — not filled across the whole pet canvas — or `cx=50%` lands at the canvas center. `MochiBody` is the reference for this pattern.

Structure of a pet (one folder each under [Components/Pets/](Motimate/Components/Pets/)): `<Name>Body.swift` renders the mood-independent body and composes `<Name>Face.swift` (the per-mood face). Face primitives split into **cross-pet ones in [Shared/](Motimate/Components/Pets/Shared/)** (`Arc`, `Cheek`, `OffsetProps`) and **per-pet ones** (each pet has its own eye: `RoundEye`, `BulbEye`, `DogEye`, `OctopusEye`, `AruticEye`, `KhinklEye`, `TomatoEye`, `SchnauzerEye`, plus e.g. `SchnauzerBrow`). Pet box/pet sizing is centralized in [Dimensions.swift](Motimate/Constants/Dimensions.swift) (`BOX_SIZE`/`PET_SIZE`/`BOX_CENTER`) — read these rather than hard-coding a viewBox or pivot.

### Animation

There is no Reanimated equivalent — animation is a **`TimelineView(.animation)` + a pure timing function** so it's testable.

- [Loop.swift](Motimate/Helpers/Loop.swift) — `LoopTiming.progress(elapsedMs, durationMs, delayMs, mode, active)` is the pure core (unit-tested in `LoopTests`), with three modes: `.pingPong` (0↔1↔0 oscillator — breathe/bob/sway), `.rise` (0→1 ramp that snaps back each cycle — rising/fading emitters), `.once` (a single ramp that holds at the end and fires `onFinished` — the entrance). `LoopClock` drives it off `TimelineView`; `PingPongLoop`/`RiseLoop`/`OnceLoop` are the view wrappers. `active: false` holds at 0 so still moods sit at rest. Easing is `MathUtils.easeInOut`.
- [PetStage.swift](Motimate/Components/Stage/PetStage.swift) — composes `Glow` + the active pet body and drives **whole-body** motion (breathe = scale, bob = offset, sway/tilt = rotation, sad = quiver) via `PetStageMotion` (a pure `values(mood, …progress) -> PetStageMotionValues` mapping, unit-tested in `PetStageMotionTests`), applied over `TimelineView` transforms. Per-mood durations live in `PetStageMotion.breathDurationMs`/`motionDurationMs`.
- [EntranceMotion.swift](Motimate/Components/Stage/EntranceMotion.swift) + `EntranceCurve` — the one-shot launch animation, gated so it plays **once per process** (`HomeView.isEntrancePlayed` is a `static` that survives view remounts).
- [Glow/](Motimate/Components/Glow/) — radial `Halo` + mood-driven emitters. Note the emitter files (`Particles`, `Clouds`, `Zzz`, `BackgroundEmitters`) exist but wiring is partial: `Glow` currently composes only `Halo`; `PhoneCanvas` renders `BackgroundEmitters`. [GlowMath.swift](Motimate/Components/Glow/GlowMath.swift) holds the interpolation/opacity math (unit-tested in `GlowMathTests`).
- [Confetti/](Motimate/Components/Confetti/) — the goal-completion celebration overlay (`Confetti`), with its particle placement/timing kept pure in [ConfettiMath.swift](Motimate/Components/Confetti/ConfettiMath.swift) (unit-tested in `ConfettiMathTests`).

### Source layout

- `Motimate/MotimateApp.swift` — `@main`; builds `SettingsStore` + `DailyStepsModel` + `CelebrationStore` and injects them; wraps `HomeView` in a `.stack` `NavigationView`.
- `Motimate/Views/` — `HomeView` (home) and `SettingsView` (goal + mode + pet + auto-night toggle).
- `Motimate/Domain/` — `Mood.swift` (Mood + `StepsConvertor`), `GameMode.swift`, `Theme.swift` (`Theme` enum + `\.theme`/`\.themeTokens` env), `Pet.swift` (`PetId` + `PETS` registry), `MessageSet.swift` (+ `pickMessages`), `Messages/<name>Messages.swift` per pet, and an empty `Story/` scaffold (story mode is **not** implemented — see [[story-mode-rendering-path]]).
- `Motimate/Persistence/` — `SettingsStore` + `CelebrationStore`, with `Storages/PersistedStorage` and the per-field `*Storage.swift` factories under `Storages/Settings/`.
- `Motimate/Steps/` — `StepReading` protocol, `StepReader` (CMPedometer), `UnavailableStepReader`, `DailySteps` (the model).
- `Motimate/Components/` — `PhoneCanvas`, `TopBar`, `MovementCard`, `PetPicker`, `ModePicker`, `Stage/` (PetStage + entrance), `Glow/`, `Confetti/`, and `Pets/` (one folder per pet + `Shared/`).
- `Motimate/Constants/` — `Fonts.swift` (`Fonts`) and `Theme/` (`Color+Hex.swift` → `Color(hex:)`, `Palette.swift` → `Palette`/`Colors`, `MoodToken.swift`, `ThemeTokens.swift`, and the per-mood `ScreenBgTokens`/`StageGlowTokens`/`StatusDotTokens` tables — verbatim from mockups), plus `Dimensions.swift`.
- `Motimate/Helpers/` — `Loop`, `MathUtils`, `ResponsiveScale`, `RoundedBoxPath`, `HapticsService` (the stateless haptics enum), `InteractiveSwipeBack` (the `.enableInteractiveSwipeBack()` modifier that restores the edge-swipe-to-go-back gesture under the hidden nav bar).
- `Motimate/Resources/` — `Assets.xcassets` (app icon, colors) and `Fonts/` (Fredoka + Nunito `.ttf`, registered via `UIAppFonts` in [Info.plist](Motimate/Info.plist); referenced as `Fredoka-SemiBold` etc. in `Fonts`).
- `MotimateTests/` — XCTest, one file per subject (`MoodTests`, `DailyStepsTests`, `ThemeTests`, `CelebrationStoreTests`, `ConfettiMathTests`, `EntranceCurveTests`, `ChromeComponentsTests`, `PetRegistryTests`, `PetStageMotionTests`, `LoopTests`, `GlowMathTests`, `SettingsStoreTests`, the `*StorageTests` including `HapticsTapStorageTests`/`HapticsAnimationStorageTests`, …); several are **ports of the RN Jest tests** and use verbatim inline snapshots (see `RoundedBoxPathTests`), so keep the `fmt`/`roundedBoxString` output byte-identical.

### Design source of truth

The HTML "deck" mockups (`Mockups/*.dc.html` here, and the fuller set under `~/Downloads/Mockups/`) define the exact palette, fonts (Fredoka/Nunito), gradients, and animation keyframes. Values in the [Constants/Theme/](Motimate/Constants/Theme/) token tables (+ [Fonts.swift](Motimate/Constants/Fonts.swift)) and the pet bodies are lifted verbatim from them — the mockups use `radial-gradient`, `filter:blur`, and elliptical `border-radius`, which is why the SVG-compat layer exists. When changing visuals, read exact values from the mockups rather than eyeballing, and diff against them.
